# P9.2 — Auth Security Hardening

> Scope: isolated P9 authentication only. Production Admin, `p8.js`, existing CRUD and the current Edit entry remain unchanged.

## Architecture

```text
GitHub Pages P9 test page
→ Apps Script `auth_start`
→ state + PKCE S256 stored server-side for <= 600 seconds
→ Google OAuth
→ redirect back to GitHub Pages
→ GitHub POSTs code + state to Apps Script `auth_finish`
→ state consumed once under ScriptLock
→ Apps Script exchanges authorization code server-side
→ ID token JWT signature verified against Google JWKS
→ iss / aud / exp / email_verified / sub / email validated
→ Members lookup
→ active / admin result
```

No Admin CRUD is exposed.

## Security properties

- Client Secret remains in Apps Script Script Properties only.
- Browser-supplied email or role is never trusted.
- `return_url` is exact-match allowlisted by `P9_ALLOWED_RETURN_URL`.
- OAuth state lifetime is 600 seconds maximum.
- State is consumed under `LockService.getScriptLock()` before token exchange, preventing replay/race double-use.
- PKCE uses S256.
- Google ID token verification does not use `tokeninfo`.
- JWT header must use `RS256` and include a Google `kid`.
- Google's rotating JWKS is fetched from `https://www.googleapis.com/oauth2/v3/certs` and cached according to Cache-Control, capped at six hours.
- Signature is verified locally as RSA PKCS#1 v1.5 SHA-256.
- Claims validation requires valid issuer, Travel Planner OAuth audience, expiration, verified email, `sub`, and email.
- Unknown signing key triggers one forced JWKS refresh before rejection.
- Members remains the final authorization source.

## Script Properties

Required, unchanged from the successful Final Bridge:

```text
P9_OAUTH_CLIENT_ID
P9_OAUTH_CLIENT_SECRET
P9_ALLOWED_RETURN_URL=https://eric851127.github.io/travel-planner-web/p9-auth-poc.html
```

`P9_REDIRECT_URI` is not used.

## Deploy

Use the existing isolated P9 Apps Script project only.

1. Replace its `Code.gs` with `apps-script/p9-auth-poc/Code.gs` from branch `p9-auth-poc`.
2. Save.
3. Run `p9AuthorizeProject` once from the Apps Script editor.
4. Run `p9RunSecuritySelfTests` from the editor.
5. Deploy a new Web App version using the existing P9 deployment configuration:
   - Execute as: Me
   - Who has access: Anyone
6. Keep the same `/exec` endpoint in the GitHub test page unless Google issues a new deployment URL.

## Deterministic self-tests

`p9RunSecuritySelfTests()` checks:

- exact return URL allowlist
- foreign return URL rejection
- RFC 7636 PKCE S256 known vector
- state TTL <= 600 seconds
- replayed state rejection
- explicitly expired state rejection
- valid claims acceptance
- wrong audience rejection
- expired token rejection
- invalid issuer rejection
- unverified email rejection
- malformed/fake JWT rejection
- BigInt RSA runtime availability

All tests must pass before browser regression testing.

## Browser / live regression matrix

| Test | Expected |
| --- | --- |
| Valid Admin | `authenticated=true`, `active=true`, `admin=true` |
| Active non-admin | `authenticated=true`, `active=true`, `admin=false` |
| Account missing from Members | `authenticated=true`, `member_found=false`, `active=false`, `admin=false` |
| Inactive member | `authenticated=true`, `active=false`, `admin=false` |
| Google login cancelled | clean rejection; no crash; OAuth query removed from address bar |
| Invalid state | `INVALID_OR_EXPIRED_STATE` |
| Expired state | `INVALID_OR_EXPIRED_STATE` |
| Replayed state | first use can proceed; second use rejected |
| Wrong OAuth audience | `INVALID_AUDIENCE` |
| Expired ID token | `TOKEN_EXPIRED` |
| Fake / modified JWT | `ID_TOKEN_INVALID` |
| Non-allowlisted return URL | `RETURN_URL_NOT_ALLOWED` |
