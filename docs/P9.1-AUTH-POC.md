# P9.1 — Admin Authentication PoC

> 狀態：isolated proof of concept。不要取代目前 production Admin，也不要修改既有 Admin deployment。

## 目標

只驗證以下鏈路：

```text
GitHub Pages / iPhone Home Screen PWA
↓
Google OAuth 2.0 / OpenID Connect redirect login
↓
Apps Script /usercallback
↓
server-side authorization-code exchange
↓
Google ID Token verification (P9.1 使用 tokeninfo)
↓
Members lookup
↓
authenticated / active / admin
↓
redirect 回 GitHub P9 test page
```

P9.1 **沒有任何 CRUD route**。

---

## 為什麼使用 Apps Script /usercallback

P9.1 不使用前端自行傳 email，也不依靠 `Session.getActiveUser()`。

OAuth Client Secret 只保存在 Apps Script Script Properties。GitHub Pages 不包含 Client Secret、Refresh Token、Service Account Key 或固定 Admin Secret。

Apps Script 官方提供 `ScriptApp.newStateToken()` 與 `/usercallback` 給 OAuth callback 使用。登入流程使用 Apps Script 產生的短效 state token，並指定 callback method；Google OAuth 完成後把 state 傳回 `/usercallback`，Apps Script 再執行指定 callback function。

## 1. 建立獨立 Apps Script Project

建立新的 Apps Script project，例如：

```text
Travel Planner P9 Auth PoC
```

只把：

```text
apps-script/p9-auth-poc/Code.gs
```

放入該 project。

不要修改 production Admin project。

---

## 2. Deploy 為獨立 Web App

Deploy → New deployment → Web app。

建議：

```text
Execute as: Me
Who has access: Anyone
```

部署後記下：

```text
https://script.google.com/macros/s/<DEPLOYMENT_ID>/exec
```

以下稱為 `P9_EXEC_URL`。

OAuth callback URI 則是同一 deployment：

```text
https://script.google.com/macros/s/<DEPLOYMENT_ID>/usercallback
```

以下稱為 `P9_CALLBACK_URL`。

---

## 3. Google OAuth Web Client

Google Auth Platform → Clients → Web application。

Authorized redirect URI 使用：

```text
P9_CALLBACK_URL
```

**不要再使用 `/exec` 當 OAuth redirect URI。**

取得：

```text
CLIENT_ID
CLIENT_SECRET
```

Client Secret 只放 Apps Script Script Properties。

---

## 4. Apps Script Script Properties

Project Settings → Script Properties：

```text
P9_OAUTH_CLIENT_ID=<CLIENT_ID>
P9_OAUTH_CLIENT_SECRET=<CLIENT_SECRET>
P9_ALLOWED_RETURN_URL=https://eric851127.github.io/travel-planner-web/p9-auth-poc.html
```

舊版 PoC 的：

```text
P9_REDIRECT_URI
```

已不再使用，可以保留但程式會忽略，或刪除。

callback URI 由 backend 依 `ScriptApp.getService().getUrl()` 自動從 `/exec` 轉成 `/usercallback`，避免手動設定兩邊不一致。

## 5. P9 test page

測試頁：

```text
https://eric851127.github.io/travel-planner-web/p9-auth-poc.html
```

第一次開啟時貼上 P9 Apps Script `/exec` URL；URL 只存在該裝置 localStorage。

頁面提供：

```text
GET transport probe
POST transport probe
Google Authentication redirect
Auth result display
```

GET / POST 仍使用 `/exec`；只有 Google OAuth callback 使用 `/usercallback`。

## 6. Authentication result

成功 Admin 預期：

```json
{
  "authenticated": true,
  "email": "admin@example.com",
  "sub": "...",
  "active": true,
  "admin": true,
  "member_found": true,
  "token_exp": 0
}
```

Google 身分有效、但不是 Admin：

```json
{
  "authenticated": true,
  "active": true,
  "admin": false
}
```

未列入 Members：

```json
{
  "authenticated": true,
  "active": false,
  "admin": false,
  "member_found": false
}
```

Token/Google validation 失敗：

```json
{
  "authenticated": false,
  "active": false,
  "admin": false,
  "error": "..."
}
```

## 7. P9.1 驗收矩陣

| Test | Expected |
| --- | --- |
| Desktop Chrome → Google login | PASS |
| iPhone Safari → Google login | PASS |
| iPhone Home Screen PWA → redirect login | PASS / UX acceptable |
| Valid Admin account | `authenticated=true`, `active=true`, `admin=true` |
| Valid non-Admin member | `authenticated=true`, `admin=false` |
| Account not in Members | `authenticated=true`, `member_found=false`, `admin=false` |
| Callback with invalid/expired state | rejected |
| Wrong OAuth client audience | rejected |
| Expired / invalid ID token | rejected |
| GitHub → Apps Script GET probe | result readable or limitation documented |
| GitHub → Apps Script POST probe | result readable or limitation documented |

## 8. Security properties already enforced in P9.1

- 不信任 browser 傳入的 email。
- OAuth authorization code 在 Apps Script backend 交換 token。
- Client Secret 不進 GitHub。
- OAuth state 使用 Apps Script `StateTokenBuilder`，短效且綁定 callback method。
- ID Token `iss`, `aud`, `exp`, `email_verified`, `sub`, `email` 必須有效。
- `aud` 必須等於 Travel Planner 自己的 OAuth Client ID。
- Members 的 `active` 與 `admin_access` 仍是最終 authorization source。
- return URL 是固定 allowlist，不接受任意 redirect target。
- PoC 沒有任何 Admin CRUD route。

---

## 9. P9.1 的刻意限制

P9.1 使用 Google `tokeninfo` 驗證 ID Token，目的只在證明整條 authentication chain。

正式 production authentication 不應長期依靠 tokeninfo；進入 P9.2/P9.3 前要改為 production-grade JWT signature verification / session architecture。

P9.1 callback 最後把測試結果放在 URL fragment 回傳 GitHub 頁面。這只是 PoC 顯示結果，不是正式 session token。

不要把這個 result 當成 P10 Admin API credential。
